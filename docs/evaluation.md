## 指标

| 指标 | 口径 |
| --- | --- |
| 整体质量通过率（quality_pass_rate / success_rate） | execution_success=true且quality_passed=true、非强制输出的用例数 / 全部用例数；v3 仅作参考，不套用 90% 目标 |
| 正常用例质量通过率（normal_quality_pass_rate） | 非故障用例（regular/uncovered/evidence）中 execution_success=true且quality_passed=true、非强制输出的用例数 / 非故障用例数；目标 ≥90%，全部用例处理完后才给出，未跑完为 null |
| 故障处理正确率（fault_handling_rate） | 故障用例（超时/非法审核/预算/取消）中被正确识别、未冒充质量通过、且失败分类符合场景的用例数 / 故障用例数；目标 100%，全部用例处理完后才给出，未跑完为 null |
| 执行完成率 | execution_status=completed的用例数 / 全部用例数 |
| 平均耗时 | 仅执行完成用例的耗时均值（包括质量未通过） |
| P95 耗时 | 执行完成用例耗时的 P95 |
| ReAct 行动次数 | Action 日志条数 |
| 关键词覆盖率 | 预期关键词对报告全文的子串匹配，忽略大小写 |
| 记忆命中率 | 存在长期记忆命中的任务占比 |

`completed_cases` 表示已处理并归档结果的用例数，不等于执行成功数；执行完成率单列，历史列表的“已处理”列使用前者。

指标目标在 metrics.py 的 TARGETS / GROUP_TARGETS 中定义，属于期望阈值，不是已获得的成绩。protocol-1 固定包含 4 个故障用例，整体质量通过率上限为 80%，因此 90% 目标只适用于非故障用例；整体通过率保留为参考。雷达图以目标值=100：耗时与行动次数达到目标即 100 分，超出目标按比例扣分，不再把“刚好达标”算成 0 分。

新记录 metric_version=3，success 是整体质量通过的兼容别名；强制输出、拒绝、审核不可用及 unknown 均不计质量成功。旧评测不回填，界面明确显示旧版执行成功口径，关键词覆盖率不能替代来源核验。

## T09已实现的离线归档

protocol-1固定20例：10常规、3模板外、3无来源/冲突/部分资料缺失（兼usage未知）、4超时/非法审核/预算/取消。evaluation/archive.py提供真实图、任务服务、SQLite、Chroma的离线执行；仅外部SDK/搜索/嵌入为合成替身，材料均明确标记。案例规范JSON SHA256和代码tag/commit/dirty、模型、提示版本、开关、随机性及冷启动记忆顺序存metadata，旧记录metadata=null，不补造版本。

v3每完成一例原子保存结果/进度/指标；部分失败保留已完成部分，质量通过率与执行完成率始终以全部20例为分母。强制输出、拒绝、未知审核、取消与失败不能算正常质量通过。正常用例质量通过率与故障处理正确率在 T09 归档后加入：T09 报告保留生成时口径，不重写历史成绩；新运行会同时输出两组比率、误放行数与失败分类。引用率是有效映射条数/全部引用条数，无引用为null；只证明结构，不证明语义蕴含或事实真实。关键词命中另列。

Token任一调用未知则汇总为null，已知费用按币种分列，部分已知不称完整总额；离线合成模型无真实单价，不生成虚构费用。P95采用nearest-rank，样本不足20退化取最大，基于执行完成且耗时已知的案例；样本数在报告中明确。人工事实抽查status=pending、sample_size=0、accuracy=null，在线实验pending，不由模型自评代替人工标注。

合成记忆登记和向量均按每轮隔离，不能读取/改写用户记忆；评测任务主题带[离线协议]，合成材料不混入真实证据。实际20例报告见verification/T09-offline-report.json和.md，分数只验证软件协议。

## T09 v2与单变量协议

界面默认通过POST /api/v2/evaluations执行protocol-1离线20例，不再默认触发v1付费冒烟。保留v1兼容入口供既有调用者使用；本轮标准测试不联网。v2要求suite_version/mode/严格feature_flags，online请求403且不建成绩；查询为统一包。角色鉴权沿用管理员/只读。C16为部分资料缺失并叠加usage未知，已知部分保留来源，未知内容明确待补充。

RAG控制模板与术语参考，memory控制本轮隔离记忆读写，review关闭时completed/not_run，不计质量通过且不入记忆。每轮独立冷启动、案例顺序固定。比较要求两轮完成、数据哈希/模型/提示/代码commit及source_hash/随机性/记忆协议一致，且只改变一个开关；条件不符409。只输出协议差值，不从合成固定响应推断在线质量提升。前端可查看旧未知版本与失败部分，不补造历史指标；只读不能运行或删除。

在线研究协议：冻结数据、代码tag/source_hash、模型供应商与请求配置、提示版本、采样参数、重复次数、顺序与冷/热记忆策略；事前取得数据去向、预计调用量与费用上限授权。对照每次仅改变一个开关，保留失败和unknown；报告有限样本、波动及是否可比。未获授权时状态pending、结果null。

人工事实抽查协议：人工选择带报告SHA256与来源片段的声明样本，记录抽样方法、总声明数/样本量、逐条supported/contradicted/insufficient及判据、标注人/时间与争议；未抽查不能给准确率。有效引用率和关键词命中不能代替这一步。本轮尚未人工标注，所有成绩均保持pending。

## 真实独立评分（EVAL-LIVE-01-02）

报告质量区可选择实际稿件或10条校准样本，在“真实独立评分”表单明确确认消费后启动。完整任务/搜索运行详情可选择案例追加真实复评；报告及当次资料与原结果SHA256绑定，原运行不改写。搜索评判S_RELEVANCE/S_COVER/S_FRESH，完整报告评判Q_SCOPE/Q_SUPPORT/Q_COVER/Q_GAP及引用结构。此判定是模型辅助结果，不是人工核验或真实事实准确率；校准记录误放行/误拒绝/未知/参考一致率，不当作被测系统质量。

评分器按以下顺序选型：优先 `EVALUATION_JUDGE_MODEL/BASE_URL/API_KEY` 独立配置；三项均未配置时使用 `BACKUP_OPENAI_*` 备用模型（与主模型通常不同源）；备用项也未配置才沿用当前 `OPENAI_*` 主模型。任意一组只配置一部分时该组不完整、评分器不可用，不会静默混用。页面显示实际模型/发送地址与来源，同模型时明确提示偏差；运行元数据记录 `judge_source`（dedicated/backup/primary）与 `judge_same_as_primary`。每次评分具有独立单次消费编号及整批调用/输入/输出/费用预算，校准10条共用本批调用上限；不读取业务Reviewer的判定作为答案。

GET live-config不调用外部服务；POST judge异步202并逐调用/逐案例保存进度。评分失败、格式错误、越界引用、预算耗尽为unknown，不冒充通过；硬引用违规仍拒绝。输入/输出Token缺失保持未知，费用按用户单价估算且不当供应商账单。关闭/重启保留已处理部分和供应商尝试。

## 首轮真实评测缺陷修复（EVAL-FIX-01）

- Q_CITE 只判引用结构：空稿、占位符、无引用、引用越界、引用无绑定分别失败；仅出现“数据待补充”不再触发失败（它是合法的缺口披露）。`[ S1]` 在落稿前与评分时归一为 `[S1]`。数字声明的映射由生产引用检查与 Q_SUPPORT 分别负责。
- 完整任务评测：单次模型超时 90 秒、completion reserve 4000、max retries 0；在线子进程期限 900 秒、离线保持 180 秒；在线授权有效期 120 分钟（搜索与独立评分仍为 30 分钟）。`metadata.execution_budget` 记录实际生效值，不再记录 30 秒。每案例模型调用上限至少 20 次、建议 40 次；低于 20 次在授权阶段直接拒绝，避免补充研究或改写前耗尽预算。
- 独立评分：`EVALUATION_JUDGE_TIMEOUT_SECONDS` 默认 60 秒（允许 5～300），同时用于供应商调用与外层等待。每次调用归档受控响应摘录（≤2000 字符）、`finish_reason` 与诊断码（空响应/JSON 无效/schema 无效/无绑定通过/截断）；异常只记类型名，不写异常消息。已有历史运行没有原始响应，不能事后补齐归因。
- 评分提示补充：资料未给出的因果、机制、分类或修订原因，以及把同一口径的来源冲突解释为品类/应用差异，均判无支持；缺口披露本身不等于引用或支持失败。
- Writer/Rewriter 增加事实口径约束：预测/预计/目标不是实绩，存量与流量不得相加，百分比变化与百分点差不得混用，同口径来源冲突须并列披露，资料未给出的解释不得补写；用户指令与资料口径冲突时以资料为准。
- 本轮只做离线门禁与契约测试，真实模型行为与评分准确率必须由新的付费复测判断；不重跑 `evaluation-runs/LIVE-20261102-01` 的归档脚本。
