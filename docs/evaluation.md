# 评测说明

## 分区题库入口（EVAL-NEXT-01）

评测中心现有总览、测试集与标准、运行、记录、复核和对照子路由；题库接入docs/evaluation-datasets/v1的88新例及原20例。来源、隐藏验收标准和合成场景仅用于管理查看，不代表实际运行结果或人工核验。接口GET /api/v2/evaluation-center/catalog及/cases/{id}使用现有鉴权和v2包，数据指纹/引用损坏明确拒绝。

专项执行与人工复核现状见下文；旧完整页面在/evaluation/protocol，支持eval查询定位指定历史。线上供应商验证仍未执行。题库随仓库本地源码读取；现有Docker构建尚未打包docs资料，Docker相关仍按既有延后范围，不宣称容器可用。

后续EVAL-NEXT-02-01增加本地机制回归：固定16个案例映射到已有真实路由/恢复测试，隔离子进程执行pytest，读取实际JUnit归档。启动/列表/详情在/api/v2/evaluation-center/runs，结果与旧协议分开。跳过、无测试、启动失败和超时均不算通过；report_quality为unknown，不证明真实备用接口或报告质量。服务关闭/重启保留已完成部分并将旧运行标为中断。需要本地pytest与测试源码，缺失时明确不可用。

专项JSON归档和临时工作目录位于DATA_DIR/evaluation-center（缺省backend/evaluation-center），默认D盘当前项目；不进Git。需要保存评测历史时，停写后连同该目录备份；临时work内只含替身数据和测试输出，可以单独清理，不能删除runs下需要保留的结果。本阶段不提供任意脚本或selector执行入口。

EVAL-NEXT-02-02新增C026/C027真实测试子进程中断演练，共18个机制映射。先确认A已落盘、B正执行或已返回未提交，再结束测试子进程，新进程读取SQLite并恢复；只保证已提交单元，B可能重放。运行详情可查看实际调用账本、演练事件及检查点恢复结果，未记录的过程不补造。子进程关闭清理只作用于自己创建的进程树；Windows与POSIX分支分别有实际运行/模拟测试，不把Windows测试当作Linux实机验收。

EVAL-NEXT-03接通人工核验：/api/v2/evaluation-center/reviews管理员追加、只读查询；题目/参考依据与某次运行结果两个目标分开，必须绑定dataset_hash。重复判定保留supersedes链；当前版本最新题目核验叠加显示，但不改冻结数据包。运行结果复核也不回写机器check_status或report_quality。记录存evaluation-center/reviews，停写备份时连同runs保存。界面可从案例详情、运行详情显式提交，人工复核页查历史；默认无法确认，未抽查项保持pending。

以下是当前实现范围；施工凭据和最终门禁以[交接](HANDOFF.md)及state.json为准，软件测试数量不是模型效果成绩。

| --- | --- | --- |

| 搜索回放 | runs / search_replay，12例 | 冻结资料卡/合成响应；URL、去重、统计期/可用性；相关性与关键证据覆盖null，不证明联网 |
| 真实搜索授权适配 | runs / search_live，8个黄金查询 | 默认拒绝无授权；单次预留后固定EXA请求，真实调用未执行；摘要/日期/估计费用不代表语义通过 |
| 固定资料报告 | grade-report，8例 | 实际提交稿件的程序检查＋独立语义适配；缺少语义评分器为unknown，硬违规优先拒绝 |
| 评分器校准 | calibrate，10例 | 预期标签只在评分后用于统计；开发/仅验收分组，未启用语义评分器时10例unknown、准确率null |
| 完整任务 | runs / full_task_local，4例 | 隔离子进程实际完整图；primary/backup/mixed三组；业务审核与独立质量分列 |
| 真实模型入口 | runs / full_task_live | 固定公开资料，仅primary；需服务端单次授权，默认403，无真实付费成绩 |
| 有限实验 | runs / bounded_experiment，6个开发输入，每轮至多2例 | 真实注入一次替身主备故障，保留初始失败；两组最多各2次冷启动重试，供应商尝试上限每次1～10 |

完整任务黄金G017～G020为evaluation_only，有限实验不会用其反思迭代；仅复用G002/G004/G008/G012/G014/G016的公开题干/资料，不传隐藏oracle。反馈是公开执行状态的确定性诊断接口，不是已安装Reflexion模型或已验证的质量增益；不写长期记忆。每次尝试增量归档，关闭/重启保留已完成部分。provider_calls为供应商边界尝试，calls为账本行数；预算拒绝可能有账本行而没有外部调用，未知不填零。

OpenJudgeAdapter仅验证预构造grader的aevaluate协议，未安装/验收SDK依赖或真实语义准确率。业务Reviewer不作为独立评分器；人工复核保留机器原始结果，校准J01～J10亦可绑定运行复核。

专项对照POST/GET comparisons保留基线/当前归档指纹，允许声明code或model_group一个维度变化。案例/顺序、资料、模型、提示、预算、记忆等需冻结且运行完整，缺失或多处变化仅并排，不算差值；原协议409单开关规则不变。逐例保存退化/改善/未知，质量未评分为null；所有尝试耗时计入，不能只挑成功案例或宣称统计显著。

真实搜索与模型各用独立授权；网页只能提交已批准编号，不能签发授权。SearchRequest的回放请求不接受消费授权字段。

专项运行、校准、复核、对照和单次消费预留均在DATA_DIR/evaluation-center。备份时停写并保存整个目录；不要只备份业务SQLite。真实调用规则见[单次授权runbook](runbooks/evaluation-paid-authorization.md)。Docker/远程部署及真实效果仍不在本轮验收内。

## 默认运行范围

评测中心默认通过v2执行protocol-1固定20例离线合成协议评测。数据集及真实执行报告见下文T09；不调用在线供应商，不代表在线效果。旧`backend/evaluation/runner.py`与v1接口保留单例冒烟兼容行为，使用既有模型配置，不能当成本轮离线默认。

v1兼容入口从case_count()取数量，既有在线行为会消耗模型与嵌入调用。v2案例集必须版本化、固定数量并记录SHA256；本轮没有执行v1在线或任何付费实验。

## 指标

| 指标 | 口径 |
| --- | --- |
| 整体质量通过率（quality_pass_rate / success_rate） | execution_success=true且quality_passed=true、非强制输出的用例数 / 全部用例数；v3 仅作参考，不套用 90% 目标 |
| 正常用例质量通过率（normal_quality_pass_rate） | 非故障用例（regular/uncovered/evidence）中 execution_success=true且quality_passed=true、非强制输出的用例数 / 非故障用例数；目标 ≥90%，全部用例处理完后才给出，未跑完为 null |
| 故障处理正确率（fault_handling_rate） | 故障用例（超时/非法审核/预算/取消）中被正确识别、未冒充质量通过、且失败分类符合场景的用例数 / 故障用例数；目标 100%，全部用例处理完后才给出，未跑完为 null |
| 执行完成率 | execution_status=completed的用例数 / 全部用例数 |
| 平均耗时 | 仅执行完成用例的耗时均值（包括质量未通过） |
| P95 耗时 | 执行完成用例耗时的 P95 |
| ReAct 行动次数 | Action 日志条数 |
| 关键词覆盖率 | 预期关键词对报告全文的子串匹配，忽略大小写 |
| 记忆命中率 | 存在长期记忆命中的任务占比 |

`completed_cases` 表示已处理并归档结果的用例数，不等于执行成功数；执行完成率单列，历史列表的“已处理”列使用前者。

指标目标在 metrics.py 的 TARGETS / GROUP_TARGETS 中定义，属于期望阈值，不是已获得的成绩。protocol-1 固定包含 4 个故障用例，整体质量通过率上限为 80%，因此 90% 目标只适用于非故障用例；整体通过率保留为参考。雷达图以目标值=100：耗时与行动次数达到目标即 100 分，超出目标按比例扣分，不再把“刚好达标”算成 0 分。

新记录 metric_version=3，success 是整体质量通过的兼容别名；强制输出、拒绝、审核不可用及 unknown 均不计质量成功。旧评测不回填，界面明确显示旧版执行成功口径，关键词覆盖率不能替代来源核验。

## T09已实现的离线归档

protocol-1固定20例：10常规、3模板外、3无来源/冲突/部分资料缺失（兼usage未知）、4超时/非法审核/预算/取消。evaluation/archive.py提供真实图、任务服务、SQLite、Chroma的离线执行；仅外部SDK/搜索/嵌入为合成替身，材料均明确标记。案例规范JSON SHA256和代码tag/commit/dirty、模型、提示版本、开关、随机性及冷启动记忆顺序存metadata，旧记录metadata=null，不补造版本。

v3每完成一例原子保存结果/进度/指标；部分失败保留已完成部分，质量通过率与执行完成率始终以全部20例为分母。强制输出、拒绝、未知审核、取消与失败不能算正常质量通过。正常用例质量通过率与故障处理正确率在 T09 归档后加入：T09 报告保留生成时口径，不重写历史成绩；新运行会同时输出两组比率、误放行数与失败分类。引用率是有效映射条数/全部引用条数，无引用为null；只证明结构，不证明语义蕴含或事实真实。关键词命中另列。

Token任一调用未知则汇总为null，已知费用按币种分列，部分已知不称完整总额；离线合成模型无真实单价，不生成虚构费用。P95采用nearest-rank，样本不足20退化取最大，基于执行完成且耗时已知的案例；样本数在报告中明确。人工事实抽查status=pending、sample_size=0、accuracy=null，在线实验pending，不由模型自评代替人工标注。

合成记忆登记和向量均按每轮隔离，不能读取/改写用户记忆；评测任务主题带[离线协议]，合成材料不混入真实证据。实际20例报告见verification/T09-offline-report.json和.md，分数只验证软件协议。

## T09 v2与单变量协议

界面默认通过POST /api/v2/evaluations执行protocol-1离线20例，不再默认触发v1付费冒烟。保留v1兼容入口供既有调用者使用；本轮标准测试不联网。v2要求suite_version/mode/严格feature_flags，online请求403且不建成绩；查询为统一包。角色鉴权沿用管理员/只读。C16为部分资料缺失并叠加usage未知，已知部分保留来源，未知内容明确待补充。

RAG控制模板与术语参考，memory控制本轮隔离记忆读写，review关闭时completed/not_run，不计质量通过且不入记忆。每轮独立冷启动、案例顺序固定。比较要求两轮完成、数据哈希/模型/提示/代码commit及source_hash/随机性/记忆协议一致，且只改变一个开关；条件不符409。只输出协议差值，不从合成固定响应推断在线质量提升。前端可查看旧未知版本与失败部分，不补造历史指标；只读不能运行或删除。

在线研究协议：冻结数据、代码tag/source_hash、模型供应商与请求配置、提示版本、采样参数、重复次数、顺序与冷/热记忆策略；事前取得数据去向、预计调用量与费用上限授权。对照每次仅改变一个开关，保留失败和unknown；报告有限样本、波动及是否可比。未获授权时状态pending、结果null。

人工事实抽查协议：人工选择带报告SHA256与来源片段的声明样本，记录抽样方法、总声明数/样本量、逐条supported/contradicted/insufficient及判据、标注人/时间与争议；未抽查不能给准确率。有效引用率和关键词命中不能代替这一步。本轮尚未人工标注，所有成绩均保持pending。

## 离线评测任务执行隔离（EVAL-ISOLATION-01）

新任务由服务端把 execution_mode、evaluation_id 与 evaluation_case_id 存入既有 tasks.metadata JSON；不新增列、不回填旧数据。普通任务恢复和重生成拒绝离线评测任务，提示到评测中心重新运行；旧任务没有模式字段时以系统既有“[离线协议] ”主题前缀保守隔离。worker 领取 queued 任务后还需匹配评测/案例的合成依赖上下文，缺失或不一致时 failed/not_run、OFFLINE_CONTEXT_REQUIRED，在 runner 前停止；评测中的取消仍可执行。新普通任务及其重生成明确记录 online，避免主题文字误判。前端列表与详情隐藏离线恢复/重生成入口，服务端仍独立校验。
