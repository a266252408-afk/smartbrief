# 技术决策与成本边界

本次沿用已存在的技术栈，不为施工方案额外引入业务依赖。具体安装版本必须由 T01 在干净环境实测后写锁文件，不凭记忆指定“最新版本”。

| 领域 | 本期选择 | 备选与取舍 | 演进路径 |
| --- | --- | --- | --- |
| 后端 | Python/FastAPI/Pydantic 模块化单体 | 重写为 TS/Go 不直接解决现有质量问题，迁移成本高 | 用服务层和 Schema 维持可替换边界 |
| 编排 | 保留 LangGraph，职责独立的研究/写作/审核 | 单 Agent 更简单，需 T09 对照证明当前循环收益；暂不拆更多 Agent | 收益不足时可简化工作流 |
| 任务执行 | 进程内受控队列、SQLite 状态，单 worker | Redis/Celery 提高跨进程可靠性但增加安装、部署和故障面，本期不引入 | task_service 契约为以后外置 Worker 预留边界 |
| 存储 | SQLite + Chroma + 本地文件 | PostgreSQL/对象存储适合更大并发，本期增加运维成本 | 仓储与文件接口隔离，迁移需评测 |
| 前端 | Vue3/Vite/TS/Element Plus；T01 增加 Vitest 与 Playwright | 纯手工测试无法重复证明状态与恢复链路 | 固定浏览器版本与离线 fixtures |
| 静态检查 | T01 引入 Ruff，类型检查沿用 vue-tsc | 不同时引入多个覆盖相同职责的格式工具 | 锁定版本，规则变更单独记录 |
| 鉴权 | 单实例管理员/只读令牌 | 注册/JWT/SSO 对单所有者展示过重 | 真正多用户再引入账号与服务端隔离 |
| 检索 | 先做好现有向量检索、阈值、选文档和证据 | BM25/重排序可能有益，但先做对照评测再决定 | 不未经评测增加模型调用 |
| 部署 | Docker Compose 两服务，完整数据卷 | Kubernetes 本期无独立扩缩容需求 | 数据目录与配置集中后易于迁移 |

LLM 仍使用用户配置的 OpenAI 兼容接口；嵌入独立配置。标准测试使用本地替身，在线实验费用默认 0（不执行），不默认替用户选供应商或发送真实资料。缓存未纳入本期强制范围，先保障可观测、预算与内容正确性。

T00 事实：系统默认 Python 缺少 LangGraph/FastMCP；本次基线测试使用临时隔离环境。T01 必须消除该机器依赖。前端已有 package-lock.json，后续使用 npm ci。禁止把临时路径、全局包碰巧可用或本机已存在 node_modules 当作可复现证明。

T01 开发锁文件至少覆盖 pytest、pytest-cov、pytest-asyncio、jsonschema 与 Ruff；前端测试依赖与浏览器版本也要固定，实际兼容版本由安装验证决定。
