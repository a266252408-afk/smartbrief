# SmartBrief 架构说明

## 访问与执行边界（T02已实现）

最小探针GET/HEAD `/healthz` 匿名；其余入口默认Bearer认证。管理员与只读令牌仅由后端环境配置，角色规则在服务层确定执行，前端统一请求头及401/403处理，令牌只保留页面内存。CORS为配置白名单；新v2会话使用统一包，既有v1成功结构保持兼容。

上传文档先校验文件名、扩展与大小，再以UUID落盘并独立记录展示名；技能ZIP整体校验穿越、链接、重复、解压大小和压缩比后再提取。技能创建/更新/删除/导入与启动metadata统一验证目录，不覆盖未知旧目录。没有原地迁移或删除旧文件。

## 研究与报告工作流

Planner 根据研究主题生成含依赖关系的步骤，优先检索报告模板与历史报告辅助规划。计划解析失败时使用降级计划。

Scheduler 反复取出依赖已满足的步骤并按 ID 顺序串行执行。Researcher 通过模型决策与 MCP 搜索收集资料；Writer 读取研究结果并检索相关术语，形成报告草稿。研究与写作步骤分别设置超时，超时会记录降级信息。

Reviewer 按数据点、来源标注、篇幅检查草稿；不通过时 Rewriter 按意见返工。达到最大轮次后仍可能强制输出，因此完成状态不等同于事实校验通过。

## 两类存储与两类记忆

SQLite 业务库存储任务、执行日志与评测记录。LangGraph 检查点使用独立 SQLite 文件保存图状态；恢复以最近的图检查点为单位，不能假定每次工具调用都已经形成可恢复快照。检查点不可用时使用内存存储。

ChromaDB 的 rag_collection 保存模板、术语和上传文档，memory_collection 保存成功任务的历史报告。上传文档经格式解析、递归分块、嵌入后入库；旧资料和记忆以内容哈希生成稳定ID；新上传片段以document_id命名空间隔离相同内容，避免合并不同上传的来源。

长期记忆关闭时跳过读写，已有数据保留。再次开启后可继续使用。知识库与长期记忆的嵌入配置使用 EMBEDDING_* 环境变量。

## 工具与技能

单智能体对话组装内置工具、MCP 工具与已启用技能的 schema，并按工具名路由。MCP 搜索作为独立子进程运行；外部 MCP 服务还可使用 HTTP 或 SSE。

四个内置技能提供搜索、分析、写作与审核。搜索调用 MCP，其余调用 LLM。技能管理器支持指令文件及参考资源。自定义Python实现与scripts默认关闭，所有者仅在信任代码时于后端环境显式启用；运行前重新检查开关，提示/context不能启用。启用并不提供Python沙箱。早期内置技能 ID 的开关配置在初始化时迁移。

## 前后端交互

FastAPI 提交接口创建业务记录并启动进程内后台任务。前端轮询任务或评测状态，展示计划、日志、审核历史与结果。历史报告从已完成任务读取，支持主题搜索、时间排序与导出。

部署和持久化配置见 [部署说明](../deploy/README.md)。当前没有独立任务队列或跨进程评测锁，部署扩展时需考虑这些约束。
