# SmartBrief 架构说明

## 访问与执行边界（T02已实现）

最小探针GET/HEAD `/healthz` 匿名；其余入口默认Bearer认证。管理员与只读令牌仅由后端环境配置，角色规则在服务层确定执行，前端统一请求头及401/403处理，令牌只保留页面内存。CORS为配置白名单；新v2会话使用统一包，既有v1成功结构保持兼容。

上传文档先校验文件名、扩展与大小，再以UUID落盘并独立记录展示名；技能ZIP整体校验穿越、链接、重复、解压大小和压缩比后再提取。技能创建/更新/删除/导入与启动metadata统一验证目录，不覆盖未知旧目录。没有原地迁移或删除旧文件。

## 研究与报告工作流

Planner 根据研究主题生成含依赖关系的步骤，优先检索报告模板与历史报告辅助规划。计划解析失败时使用降级计划。

Scheduler 反复取出依赖已满足的步骤并按 ID 顺序串行执行。Researcher 通过模型决策与 MCP 搜索收集资料；Writer 读取研究结果并检索相关术语，形成报告草稿。研究与写作步骤分别设置超时，超时会记录降级信息。

Reviewer 按数据点、来源标注、篇幅检查草稿；不通过时 Rewriter 按意见返工。达到最大轮次后强制输出仍保留rejected与passed=false；解析/调用失败为unavailable。空稿、失败占位或返工失败为failed/not_run。执行完成与审核通过分列持久化，未知历史质量为unknown；v2任务/报告读取统一包，v1保留结构并新增双状态。审核通过只代表约定审核结果，不等同于外部事实已核验。

## 两类存储与两类记忆

SQLite 业务库存储任务、执行日志与评测记录。LangGraph 检查点使用独立 SQLite 文件保存图状态；恢复以最近的图检查点为单位，不能假定每次工具调用都已经形成可恢复快照。检查点不可用时使用内存存储。

ChromaDB 的 rag_collection 保存模板、术语和上传文档，memory_collection仅准入新的completed/passed报告；旧记忆隔离和删除治理仍待T06。上传文档经格式解析、递归分块、嵌入后入库；旧资料和记忆以内容哈希生成稳定ID；新上传片段以document_id命名空间隔离相同内容，避免合并不同上传的来源。

长期记忆关闭时跳过读写，已有数据保留。再次开启后可继续使用。知识库与长期记忆的嵌入配置使用 EMBEDDING_* 环境变量。

## 工具与技能

单智能体对话组装内置工具、MCP 工具与已启用技能的 schema，并按工具名路由。MCP 搜索作为独立子进程运行；外部 MCP 服务还可使用 HTTP 或 SSE。

四个内置技能提供搜索、分析、写作与审核。搜索调用 MCP，其余调用 LLM。技能管理器支持指令文件及参考资源。自定义Python实现与scripts默认关闭，所有者仅在信任代码时于后端环境显式启用；运行前重新检查开关，提示/context不能启用。启用并不提供Python沙箱。早期内置技能 ID 的开关配置在初始化时迁移。

## 前后端交互

FastAPI 提交接口创建业务记录并启动进程内后台任务。前端轮询任务或评测状态，展示计划、日志、审核历史与结果。历史报告从已完成任务读取，支持主题搜索、时间排序与导出。

部署和持久化配置见 [部署说明](../deploy/README.md)。当前没有独立任务队列或跨进程评测锁，部署扩展时需考虑这些约束。

## 来源与引用溯源（T04已实现）

搜索结果由确定性服务转为任务内Evidence，规范化HTTP(S)URL并去重，固定S1/S2编号、标题、收集时间和证据片段；失败搜索及无效链接不会生成证据。证据保存在任务JSON列，历史记录没有来源时保持空列表，不从旧报告猜测。v2任务sources使用统一响应包，v1详情/报告增加来源及引用字段。

Scheduler在写作前构建同任务来源；Writer和Rewriter收到按项裁剪、总预算约束的完整JSON资料，资料不提升为系统指令。确定性校验检查声明段落与编号、来源归属/存在/失效和返工丢编号；不通过时模型不能覆盖为passed。此检查仅证明结构可追溯，不代表事实已核实或语义必然受片段支持。

两个报告视图共用净化渲染，编号跳转到来源卡片，未知/无效来源明确标记；外链只接受无凭证HTTP(S)，源标题/片段及模型HTML按文本处理，防止脚本和锚点伪造。Word与PDF使用同一份包含来源附录的内容；Word仍为HTML兼容.doc，PDF保留编号和可见来源文本，不承诺PDF内页锚点交互。

## 上传文档参与写作（T05已实现）

首页可选择至多20个具有document_id的上传资料。知识库按ID展示、查看与删除，同名上传相互独立；无ID的历史条目不推断归属，可重新上传。v1未选资料保持原请求/响应兼容；v2新增knowledge/documents/{document_id}与tasks/{task_id}/retrievals统一包。

文档检索服务先用upload类别+document_id约束Chroma，再按top_k、相似度阈值与完整片段字符预算筛选。RetrievalOptions默认5/0.35/6000，可由服务调用方显式配置；检索记录保存实际参数。缺选取、无命中、相关性不足、超预算、所选缺失、嵌入失败与索引失败独立记录，不以随机材料回填。模板用于规划、术语用于定义，上传片段作为事实资料。

检索快照存于SQLite并进入图检查点；来源含document_id/chunk_id/可得页码/分数/时间。Writer与Rewriter共用任务内证据编号，文档文字只进用户资料区。写作/审核/返工前复核索引，删除后的来源不再参与新任务或通过当前审核。旧任务片段保留，读取时标注source_deleted，保留历史审核事实；索引故障返回错误，不冒充删除。删除当前仅删除索引，服务器上传原文件保留，完整数据生命周期治理见T10。

详情/报告共享检索解释卡片；来源附录和Word/PDF保留文档标识、片段、页码和分数。页面将来源内容按文本显示，映射可追溯不代表事实真实。标准验证仅离线模型/嵌入替身，未执行在线语义质量或提示注入效果评测。

模板结构检索仅取匹配模板的Markdown标题（最多10个、每个120字符）作为Planner非可信结构参考，不传正文、不变成报告Evidence；检索不可用时跳过并使用原规划流程。v2任务详情/报告检测到损坏来源或检索记录时返回TASK_DATA_INVALID统一错误包。

## 长期记忆质量与生命周期（T06）

SQLite memory_entries是可信准入/生命周期权威登记，Chroma memory_collection只负责相似结构。remember保留签名，但检查真实任务completed/passed、未强制输出、当前来源映射及正文一致性；调用参数不能授权质量。模型记录当前配置名、供应商版本未知为null，提示实现版本有标识。新记忆按task_id+report_hash稳定编号，索引内容哈希绑定；写入中断可复用已有向量，未完成登记不会召回，删除/失效版本不能复活。

旧向量原样保留，管理为unverified，不自动升级。召回仅从当前任务/正文/来源仍合格的active登记中检索，并复核向量内容；Planner只取历史标题结构，不用历史正文替代当前证据。开关只影响读写，不删除数据。

v2 memory提供分页、五状态过滤和管理员墓碑删除；索引删除失败也不恢复召回资格。原任务删除与记忆失效同SQLite事务。regenerate创建新任务并保存不可变regenerated_from，原报告和仍合格的原记忆保留；新任务重新检索所选文档并独立审核准入。v1响应形状保持，memory/status.count明确统计合格active记录，关闭时仍0。

知识库按需打开管理视图，未知模型版本/时间不捏造；索引故障明确不可用而非空库。只读可查询不可删除或重新生成。任务详情支持重新生成与来源任务展示，路由切换重启轮询并拒收旧ID迟到响应。在线效果未评测，具体边界与凭据见T06 SDD和verification/T06.json。

## 模型用量与预算（T07）

所有报告Agent通过ContextVar绑定task_id/agent；单智能体对话使用独立chat_UUID。llm/client只调用OpenAI兼容SDK，SDK重试为0，业务层按MODEL_MAX_RETRIES重试超时/连接/429/5xx；每次尝试有唯一call_id、attempt、模型、耗时、结果与固定错误码。调用前SQLite原子写占位及预留，结束后写入供应商usage，取消也记账；失败/崩溃保留unknown，不记录prompt或密钥。仓储/预算持久化失败和预算不足传播到工作流失败终态，不由Agent降级吞掉。

MAX_TASK_TOKENS默认20000，MODEL_COMPLETION_RESERVE默认2048，MODEL_TIMEOUT_SECONDS默认60，MODEL_MAX_RETRIES默认1。消息及工具UTF-8字节数加完成预留用于调用前保守估算；成功已知Token后按供应商值结算，未知/失败按预留扣账，旧未知无预留按当前预算扣满。同任务并发事务保护，恢复读取持久化账本。分词器和供应商用量可能不同，不能宣称严格Token或金额封顶。

MODEL_PRICES_JSON可按模型指定每百万输入/输出单价与三字母币种，无默认值；费用按调用时配置估算并持久化，价格变化不重估历史，不同币种分开统计。v2 tasks/{id}/usage统一包对管理员/只读开放，未知任务404、损坏/不可用503；旧任务无记录显示未知而非零，v1形状保留。TaskDetail按需查看和轮询，切任务/卸载拒绝迟到响应；JSON导出只含结构化账本，费用部分已知时不称总额。

## 受控任务生命周期（T08）

单worker的TaskService持有句柄和信号量，MAX_CONCURRENT_TASKS默认2。v2创建返回202/queued，v1保留200与原键并报告真实queued；提交、重生成、恢复与评测共用队列。SQLite条件领取生成内部运行租约，重复调度不重复执行。同业务库实例锁拒绝第二个任务worker；环境workers配置>1也拒绝。关闭等待句柄并将running留为paused，queued可靠保留；启动只领取queued，原running先转paused。

取消先在事务中提交cancelled/not_run和唯一审计，再通知句柄；完成和取消用running/租约条件竞争，最终状态与完整图日志同事务。成功取消后旧回调不能完成任务或进入后续Agent/记忆。不可中断的线程I/O可能结束当前操作，租约阻止后续步骤与结果写入；已完成任务不接受取消。

动作凭据与创建/取消/恢复/重生成同事务，Idempotency-Key仅存SHA256摘要；按动作、目标和规范请求体校验，冲突409，重复同请求返回历史接收结果。无Key的创建不保证去重。删除任务不会清除幂等凭据或令历史Key重新生成任务。恢复仅paused/failed可重新排队，queued/running重复请求不新增执行，cancelled/completed拒绝；恢复不清空用量预算。

持久化图有next节点才称checkpoint续跑；终止、缺失、损坏或执行时失效会明确restart，从头重新检索。SQLite检查点不可用时清理连接后使用临时内存状态，不修改损坏原文件。resume_mode是实际运行结果的一部分；内部run_token/resume_requested不进入API。旧记录不伪造恢复模式或动作历史。

前端创建/取消/恢复/重生成用v2并在失败重试时保留同一Key；详情与列表识别queued/cancelled，队列持续轮询，运行中可取消。后台轮询不遮挡操作，按请求版本号拒收同ID和跨ID迟到响应；只读禁写，失败不假称成功，实际从头重试/断点续跑明确展示。Windows实例互斥实际验证；Linux实例锁分支和容器恢复留T10/T13，不以本机测试冒充跨平台验收。

## 版本化离线评测（T09）

v2评测API经evaluation_service进入固定20例协议集。每案例复用真实TaskService/LangGraph/状态、预算与仓储，外部模型/搜索/嵌入通过ContextVar替换为明确合成依赖；独立Chroma、SQLite记忆登记与检查点禁止读写用户记忆或向量。评测任务主题带离线标识。用户全局开关不改变，RAG/记忆/审核开关仅当前上下文生效。

评测metadata记录数据集版本/hash、模型/提示、code_tag/commit/dirty/source_hash与随机性、冷启动/顺序；旧记录保持null。逐例结果/进度/指标同事务保存，失败保留部分，启动/关闭清理中断。执行与质量分离，无引用/未知用量/未知费用不伪造0；人工事实抽查及在线效果pending。比较要求同版本、单开关变化，仅输出合成协议差值。v1兼容，前端默认v2离线，旧版与失败可解释展示。
